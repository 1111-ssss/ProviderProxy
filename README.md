# provider_proxy

Локальный OpenAI-совместимый прокси для opencode с автоматическим переключением провайдеров.

Одна «модель» в opencode = цепочка upstream-провайдеров в порядке приоритета. Если у провайдера
кончился дневной лимит (429), он упал (5xx) или не отвечает (сеть/таймаут) — прокси сам
переключается на следующего в цепочке.

## Как работает

- Эндпоинты: `POST /v1/chat/completions`, `GET /v1/models` (OpenAI-совместимо).
- Failover срабатывает на: HTTP 402, 403, 408, 429, 5xx, обрыв сети, таймаут заголовков (`headerTimeoutSec`, по умолчанию 20 с),
  а также на 400 с «unsupported content» — например, провайдер не принимает картинки (`image_url`).
- После 429 провайдер уходит в кулдаун на `limitCooldownSec` (по умолчанию 5 минут),
  после 5xx/сети — на `errorCooldownSec` (30 с). Если провайдер прислал `Retry-After`, используется он.
- Переключение только до первого токена ответа: если стрим уже пошёл, ретраить нельзя.
- Кулдауны в памяти: рестарт прокси их сбрасывает.

## Запуск

    node server.mjs                      # при первом запуске возьмёт config.example.json (или пустой конфиг);
                                         # первый save из GUI создаст config.json
    node test.mjs                        # smoke-тест failover

Прокси должен быть запущен, пока работает opencode.

## GUI

Открой `http://127.0.0.1:8787/` в браузере. Разделы — вкладками сверху (какая была открыта, помнится
в браузере):

1. **Провайдеры** — «+ Добавить провайдера»: имя, baseURL, apiKey и необязательная ссылка для чекина.
   Кнопка «Чекин» открывает checkin-страницу (если ссылка задана), «Открыть все чекины» — сразу все.
2. **Модели провайдеров** — выбери провайдера и отметь галочками модели, которые у него есть. Список
   берётся с его `/v1/models` и из сохранённых, недостающую можно вписать вручную и отфильтровать по
   имени. Выбор сохраняется локально в `config.json`.
3. **Цепочки моделей** — «+ Добавить модель»: имя + порядок провайдеров, подменяющих друг друга при
   ошибке или дневном лимите. В цепочку добавляются модели из шага 2 (или произвольный ID вручную);
   порядок ↑/↓ = приоритет failover. «Изменить» открывает тот же диалог.
   Кнопка «⟳ Синхронизировать с opencode» записывает список цепочек в конфиг opencode — смотри
   «Подключение к opencode».
4. **Логи** — живой хвост вывода прокси: последние 500 строк, держатся в памяти и вытесняются
   новыми сами (`PP_LOG_LINES` меняет лимит).
5. **Usage** — дашборд по данным в памяти: запросы, failover, 429/ошибки по каждому провайдеру,
   токены вход/выход по провайдерам и моделям, кто сейчас в кулдауне. Токены видны, когда upstream
   их присылает; счётчики обнуляются при перезапуске прокси.
6. **Настройки** — port, authToken, кулдауны, таймаут.
- Всё сохраняется в `config.json` сразу; прокси подхватывает изменения без рестарта (кроме `port`).

## Приватность

Данные не отправляются никуда, кроме самих провайдеров:

- ключи хранятся только в локальном `config.json`;
- apiKey уходит только на `baseURL` своего провайдера — с запросами моделей и при загрузке `/v1/models`;
- GUI не подключает внешних скриптов и стилей и обращается только к локальному прокси — это
  проверяется тестом (`node test.mjs`);
- чекин-ссылки открываются в браузере только по твоему клику.

## Конфиг

| Поле | Что делает |
|---|---|
| `port` | порт прокси (по умолчанию 8787) |
| `authToken` | если задан — клиенты обязаны слать `Authorization: Bearer <authToken>` |
| `limitCooldownSec` / `errorCooldownSec` | кулдаун после 429 / после 5xx и сетевых ошибок |
| `headerTimeoutSec` | сколько ждать заголовков ответа от upstream |
| `providers.<имя>` | провайдер: `baseURL`, `apiKey`, `models` (выбранные ID моделей, массив), `checkin` (необязательная ссылка), опционально `headers` |
| `models.<имя>.upstreams[]` | цепочка: `provider` (имя из `providers`), `model` (реальный ID модели у провайдера) |
| `opencodeConfig` / `opencodeProvider` | куда и в какой провайдер писать карту моделей для opencode (по умолчанию `~/.config/opencode/opencode.jsonc` и `provider-proxy`) |

Раньше upstream'ы задавались инлайном (`baseURL`/`apiKey` прямо в цепочке) — такой формат по-прежнему читается.

Каждый upstream обязан давать `POST {baseURL}/chat/completions`. Это умеют: OpenAI, OpenRouter,
Anthropic (`https://api.anthropic.com/v1`), Gemini (`https://generativelanguage.googleapis.com/v1beta/openai`),
DeepSeek, Groq, Together, vLLM, Ollama (`http://127.0.0.1:11434/v1`) и т.д.

## Подключение к opencode

Провайдер в конфиге opencode (`~/.config/opencode/opencode.jsonc`):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "provider-proxy/glm-5.3-flash",
  "providers": {
    "provider-proxy": {
      "package": "aisdk:@ai-sdk/openai-compatible",
      "name": "Provider Proxy",
      "settings": {
        "baseURL": "http://127.0.0.1:8787/v1",
        "apiKey": "auth"
      },
      "models": {
        "glm-5.3-flash": { "name": "GLM 5.3 Flash (proxy)" },
        "deepseek-v4.1-flash": { "name": "Deepseek v4.1 Flash (proxy)" }
      }
    }
  }
}
```

Три вещи, без которых opencode покажет «No items available»:

1. **`apiKey` должен совпадать с `authToken` прокси.** Без него opencode не шлёт `Authorization`,
   прокси отвечает 401, и даже готовые модели не работают.
2. **Карта `models` обязательна.** opencode у кастомного провайдера (`aisdk:@ai-sdk/openai-compatible`)
   не спрашивает `GET /v1/models` — список моделей он берёт только из конфига. Имена в `models` =
   имена цепочек из `config.json` прокси.
3. **Пакет** — `aisdk:@ai-sdk/openai-compatible` (не `@ai-sdk/openai`: тот умеет брать список
   моделей сам, но шлёт запросы в формате Responses API, который прокси не переводит).

Модели без явного `limit` получают в opencode лимиты по умолчанию — пропиши `limit.context` под
реальное окно модели.

### Автосинхронизация

Прокси сам дописывает карту `models` (и `apiKey`) в конфиг opencode:

- при каждом сохранении из GUI и по кнопке «⟳ Синхронизировать с opencode»;
- файл по умолчанию `~/.config/opencode/opencode.jsonc`, провайдер — `provider-proxy`.
  Переопределяется в `config.json`: `"opencodeConfig": "...", "opencodeProvider": "..."`;
- старый конфиг сохраняется рядом как `opencode.jsonc.bak`;
- имена моделей, которые ты переименовал руками, сохраняются; провайдеры, кроме нашего, не трогаются;
- если в файле появятся комментарии (JSONC) — синхронизация пропускается, об этом будет запись
  во вкладке «Логи».

Новые модели opencode подхватывает сам (файл перечитывается на лету). Если список не обновился —
  `opencode reload` или перезапуск opencode.

## Ярлык в KRunner (KDE)

`launch.sh` поднимает прокси (лог — `server.log` рядом со скриптом), открывает GUI в браузере
и живёт, пока открыта вкладка: закрыл её — через ~15 секунд без активных запросов сервер
выключится сам. Ярлык — `~/.local/share/applications/provider-proxy.desktop`, в KRunner ищи
«Provider Proxy».

Внимание: правило распространяется и на сервер, запущенный вручную — если открыть GUI и закрыть
вкладку, он тоже выключится. Если вкладка не открывалась — сервер работает, пока не остановишь сам.

## Ограничения

- Только OpenAI-совместимые upstream'ы, без трансляции нативных протоколов.
- Failover только до первого токена стрима.
- Слушает только 127.0.0.1; без `authToken` любой локальный процесс может пользоваться твоими ключами.
- Счёт токенов — по тому, что прислал upstream: если провайдер их не шлёт, в Usage будет ноль.
